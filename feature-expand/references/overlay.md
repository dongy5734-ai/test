# 剧本：弹层（弹窗 / 抽屉 / 对话框 / 确认框）

一句话：用户要「弹窗、弹层、抽屉、对话框、确认一下」这类东西时，用这份剧本。

## 第一步：先搜项目

必须先做，再写代码：

1. 搜代码库里有没有现成的 Modal / Dialog / Drawer / Popconfirm 组件。
2. 搜项目里其他弹层怎么管理开关状态（受控 props、hook、全局服务），跟着同一套写。
3. 有就复用。禁止项目里已有 Modal 还自己用 fixed 定位手搓一个。

## 默认决策表（逐行填，不许留空）

| 维度 | 默认 | 升级条件 |
| --- | --- | --- |
| 关闭方式 | Esc 可关、点遮罩可关、右上角有关闭按钮 | 危险确认框 / 表单填了一半 → 禁用遮罩关闭，只留按钮和 Esc |
| 焦点管理 | 打开后焦点进入弹层（聚焦陷阱），Tab 不跑到背景页；关闭后焦点回到触发按钮 | 无升级项，这是底线 |
| 危险操作文案 | 确认按钮写具体动作：「删除」「移除成员」，且为危险色；禁止写「确定」 | 无升级项，这是底线 |
| 确认框内容 | 写清后果和对象：「删除订单 #1234？删除后不可恢复。」 | 不可逆且影响大 → 要求输入名称二次确认 |
| 提交中 | 弹层里有提交动作时：按钮禁用 + loading，提交中禁止关闭弹层 | 无升级项 |
| 内容滚动 | 内容超高时弹层内部滚动，头部和按钮区固定 | 内容很长（如详情页级别）→ 用抽屉而不是弹窗 |
| 背景滚动 | 弹层打开时锁定背景页滚动 | 无升级项 |
| 关闭后状态 | 弹层关闭即重置内部临时状态；下次打开不残留上次的输入 | 用户明确要求保留草稿才保留 |

## 必须实现的状态（缺一个就是没完成）

- 加载：弹层内容需要请求时，打开后先显示加载态，不是空白弹层。
- 失败：内容加载失败显示错误 + 重试，不是永远转圈。
- 提交中：确认按钮禁用 + loading。
- 关闭：Esc、遮罩（危险场景除外）、关闭按钮三条路都通，关闭后焦点归还。

## 禁止事项（弱模型最爱犯的）

- 禁止没有 Esc 和遮罩关闭。用户被困在弹层里出不去，这是事故。
- 禁止没有聚焦陷阱。Tab 一按焦点跑到背景页上，键盘用户直接废掉。
- 禁止危险操作按钮写「确定」。删库确认框上写「确定」，手滑就是事故。
  错：`[取消] [确定]`。对：`[取消] [删除]`（删除为危险色）。
- 禁止确认框只写「确认执行此操作吗？」。必须写清删的是什么、后果是什么。
- 禁止弹窗套弹窗超过两层。第二层还不够用，说明该改成页面。
- 禁止顺手加最小化、拖拽、多窗口管理。用户没要就不做。

## 短例子

用户原话：「删除的时候弹个确认框。」

你应该产出：

- 复用项目 Modal/Popconfirm 组件。
- 文案：「删除订单 #1234？删除后不可恢复。」按钮：`[取消] [删除]`，删除为危险色。
- 遮罩点击不关闭（危险确认），Esc 可关，删除中按钮禁用 + loading。
- 删除成功后关闭弹层、刷新列表；失败保留弹层并展示原因。

不该产出：`confirm('确定吗?')`，或一个按钮写「确定」、点遮罩就没了的弹窗。

## 最小路径（用户说「简单弹一下就行」时）

- 可以砍：输入名称二次确认、抽屉化。
- 不许砍：Esc 关闭、危险按钮具体文案、提交中禁用、失败提示。
- 仍禁止裸 happy path。
