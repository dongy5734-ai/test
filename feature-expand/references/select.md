# 剧本：选择器（下拉 / 多选 / 搜索选择 / 级联）

一句话：用户要「下拉框、选择、选项、多选、级联」这类东西时，用这份剧本。
全文统一叫「选择器」。用户嘴里的「下拉框 / 下拉 / select」都是它。

## 第一步：先搜项目

必须先做，再写代码：

1. 搜代码库里有没有现成的 Select / Picker / Dropdown / Combobox 组件
   （常见位置：`components/`、`ui/`、设计系统包、antd/element/mui 等已装依赖）。
2. 有就复用，只补缺的行为（搜索、状态、键盘）。
3. 禁止项目里已有 Select 还自己手写一个。
4. 禁止为一个选择器新装 UI 库。

## 默认决策表（逐行填，不许留空）

| 维度 | 默认 | 升级条件 |
| --- | --- | --- |
| 单选/多选 | 单选 | 用户明确说「可多选 / 可以选多个」才做多选 |
| 数据来源 | 选项必须来自 props 或接口，禁止在组件里写死业务选项；来源不明时先做成 props 传入，再最多问 1 句「接口是全量返回还是分页？」 | 用户指明接口则走接口 |
| 搜索 | 数据来源或数量未知 → 先按会超过 20 项处理，做本地过滤；已确认固定 ≤20 → 不做搜索；全量且数量不大 → 本地过滤 | 接口分页，或接口数据会随业务增长 → 服务端搜索 + 防抖 300ms + 竞态保护（见下） |
| 数据量策略 | ≤50 全量渲染；50–200 全量 + 本地过滤 | >200 虚拟列表或接口分页；接口本身分页则跟接口走 |
| 防抖 | 服务端搜索必须防抖 300ms，请求带竞态保护（丢弃过期响应） | 本地过滤不需要防抖 |
| 已选回显 | 关闭面板后输入框仍显示当前值；多选显示标签，超过 3 个显示「+N」 | 无升级项，这是底线 |
| 清除 | 单选可清空（有清除按钮）；多选每个标签可单独删，另有全部清除 | 用户说不可为空则去掉清除 |
| 键盘 | 聚焦后回车/下箭头打开；上下移动高亮；回车选中；Esc 关闭；输入即过滤 | 无升级项，这是底线 |
| 禁用 | 支持整体禁用和单个选项禁用，禁用项不可被键盘选中 | 无升级项 |

## 必须实现的状态（缺一个就是没完成）

- 空：一个选项都没有 → 显示「暂无选项」，不是空白面板。
- 加载：接口拉取中 → 面板里有 loading 提示，不是闪一下空白。
- 无匹配（做了搜索时必须）：搜了没结果 → 显示「无匹配结果」，不是空白。
- 失败：接口挂了 → 显示错误 + 重试按钮，点重试能重新请求。
- 禁用：禁用时不可打开面板、样式可辨认。

## 禁止事项（弱模型最爱犯的）

- 禁止用原生 `<select>` 硬撑大数据或需要搜索的场景。
  原生 `<select>` 只允许用在：选项固定 ≤ 10 个、不需要搜索、项目里没有现成 Select 组件时。
- 禁止一次把 1000 个 option 塞进 DOM。>200 必须虚拟列表或分页。
- 禁止只做 happy path。上面 5 个状态一个都不能少。
- 禁止把选项写死在组件里还不留数据入口。选项来源必须是 props 或接口。
- 禁止做成中台筛选系统。用户要选择器，不要顺手加标签管理、历史记录、收藏。

## 短例子

用户原话：「实现一下下拉框，选部门用的。」

你应该产出：

- 复用项目已有 Select 组件（若有）。
- 单选（没说多选）。部门数据来自接口 → 问一个架构问题：「部门接口是全量返回还是分页？」
- 全量且数量不大 → 本地过滤；接口分页或数据会随业务增长 → 服务端搜索 + 防抖 300ms + 竞态保护。
- 空 / 加载 / 无匹配 / 失败重试 / 禁用，五态齐全。
- 键盘可用，关面板后回显已选部门名。

不该产出：一个写死 5 个部门的 `<select>`；也不该产出带「常用部门收藏」的筛选系统。

## 最小路径（用户说「先随便做个能选的」时）

- 可以砍：搜索（无匹配态随之不需要）、键盘增强、虚拟列表。
- 不许砍：空态、加载态、失败态、禁用态、已选回显。
- 仍禁止裸 happy path。
