# 剧本：表单（表单 / 提交 / 新增 / 编辑 / 上传）

一句话：用户要「表单、提交、填写、新增、编辑、上传」这类东西时，用这份剧本。

## 第一步：先搜项目

必须先做，再写代码：

1. 搜代码库里有没有现成的 Form / FormItem / 校验方案（如 antd Form、react-hook-form、
   vee-validate、zod schema）。
2. 搜有没有别的页面已有类似表单，抄它的字段布局、校验写法、提交流程。
3. 有就复用。禁止项目里已有表单方案还自己用 useState 手搓一套校验。

## 默认决策表（逐行填，不许留空）

| 维度 | 默认 | 升级条件 |
| --- | --- | --- |
| 校验时机 | 默认路径必须做：失焦校验单字段 + 提交校验全部并聚焦第一个错误 | 用户明确说「只要最小实现 / 先出个 demo / 不要多余功能 / 先能提交就行」时可砍失焦，但提交时全量校验、字段旁错误、聚焦第一个错误仍必须。不是所有任务都把失焦当底线 |
| 错误展示 | 错误显示在对应字段旁边，写清哪里错、怎么改（如「手机号必须是 11 位数字」） | 无升级项。禁止只 toast「失败」 |
| 必填标记 | 必填字段带标记（如 *）；标签文案和字段一一对应 | 无升级项 |
| 提交中 | 提交按钮禁用 + loading；整个提交期间禁止重复提交 | 无升级项，这是底线 |
| 失败后 | 保留用户已填的全部数据；展示后端返回的可读错误；可直接重试 | 后端返回字段级错误 → 映射到对应字段旁 |
| 成功后 | 给成功反馈；新增场景重置表单，编辑场景保留数据并提示已保存 | 用户指定跳转则跳转 |
| 编辑回填 | 仅编辑场景必须：先拉详情回填，回填前表单区域显示加载态；新增/纯提交场景不做回填 | 无升级项。禁止凭空做一套编辑流程 |
| 离开保护 | 不做 | 用户明确要求「防止误关丢数据」才做 |
| 上传字段 | 显示上传进度和失败重传；限制类型和大小并在选文件时就提示 | 无升级项（有上传字段时是底线） |

## 必须实现的状态（缺一个就是没完成）

- 校验错误：字段旁有具体错误文案，提交时聚焦第一个错误。
- 提交中：按钮禁用 + loading，表单不可再触发提交。
- 失败：数据还在，错误原因可读，能重试。
- 成功：有明确反馈，用户知道提交成功了。
- 编辑加载（仅编辑场景必须）：回填数据没到之前有加载态，不是先闪一个空表单。
  新增/纯提交场景不做回填，禁止凭空做一套编辑流程。

## 禁止事项（弱模型最爱犯的）

- 禁止提交按钮不禁用。连点两下就发两个请求，这是事故。
- 禁止失败后清空表单。用户填了 20 个字段，失败一次全没了，这是事故。
- 禁止错误只有一句「失败」或「操作失败」。必须说清哪个字段、什么原因。
- 禁止把校验只写在前端提示文案里而不真正拦截提交。
- 禁止顺手加草稿箱、自动保存、字段联动配置。用户没要就不做。

## 短例子

用户原话：「加个提交，用户信息那个页面。」

你应该产出：

- 复用项目 Form 方案。问：「提交到哪个接口？后端有字段校验规则要对齐吗？」
- 失焦校验 + 提交全量校验，错误显示在字段旁。
- 提交中按钮禁用 + loading；失败保留数据、展示后端错误、可重试；成功给反馈。
- 确认是编辑场景才先拉详情回填，回填期间有加载态；纯提交场景不做回填。

不该产出：几个 input + 一个能连点的按钮，失败 toast「失败」然后表单清空。

## 最小路径（用户说「先能提交就行」时）

- 可以砍：失焦校验、编辑回填的骨架屏、上传进度条。
- 不许砍：提交时全量校验并聚焦第一个错误、字段旁错误文案、提交中禁用按钮、失败保留数据。
- 仍禁止裸 happy path。
