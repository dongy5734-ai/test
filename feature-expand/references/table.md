# 剧本：表格列表（表格 / 列表 / 数据展示）

一句话：用户要「表格、列表、把数据展示出来」这类东西时，用这份剧本。

## 第一步：先搜项目

必须先做，再写代码：

1. 搜代码库里有没有现成的 Table / List / DataGrid 组件，以及现成的分页组件。
2. 搜有没有别的页面已经在展示类似数据，抄它的结构和请求写法。
3. 有就复用。禁止项目里已有 Table 还自己手写 `<table>` + 样式。

## 默认决策表（逐行填，不许留空）

| 维度 | 默认 | 升级条件 |
| --- | --- | --- |
| 数据来源 | 问一个架构问题：「接口是分页返回还是一次全返？」 | 这是本剧本唯一值得问的问题 |
| 分页 | 接口分页 → 传 page/pageSize，翻页重新请求；一次全返且 ≤100 条 → 前端分页 | >1000 条且接口不分页 → 先要求接口分页，做不到再上虚拟滚动 |
| 每页条数 | 默认 10 或 20，跟项目里其他表格保持一致 | 用户指定就用用户的 |
| 列对齐 | 文本左对齐；数字、金额右对齐；操作列固定在最右 | 无升级项，这是底线 |
| 空值单元格 | 显示「-」 | 无升级项。禁止渲染出 undefined / null / NaN |
| 长文本 | 超宽省略号 + hover 提示完整内容 | 用户要求换行则换行 |
| 时间列 | 格式化成项目惯用格式（先搜项目里的时间格式化工具） | 无升级项 |
| 排序/筛选 | 不做 | 用户明确要求才做；做了也只做用户点名的列 |
| 操作列 | 用户提到编辑/删除才加；删除必须走确认弹层（读 overlay.md） | 无升级项 |
| 刷新 | 增删改成功后重新拉当前页数据 | 无升级项，这是底线 |

## 必须实现的状态（缺一个就是没完成）

- 空数据：显示「暂无数据」空态（复用项目 Empty 组件），不是一个光秃秃的表头。
- 加载：骨架屏或表格内 loading，翻页时也要有。禁止加载中显示「暂无数据」。
- 失败：显示错误原因 + 重试按钮，点重试重新请求当前页。
- 翻页：翻页参数变化触发重新请求（接口分页时），页码状态和数据一致。

## 禁止事项（弱模型最爱犯的）

- 禁止 slice 前 10 条假装分页。分页必须真的能翻到第 2 页并看到不同数据。
- 禁止接口支持分页却把全量数据拉到前端。
- 禁止表头写死但数据字段对不上，渲染出一列 undefined。
- 禁止加载中和空数据共用一个状态——请求没回来之前不许显示「暂无数据」。
- 禁止顺手加导出 Excel、列设置、全局筛选区。用户没要就不做。

## 短例子

用户原话：「把订单列表展示出来。」

你应该产出：

- 复用项目 Table 组件。问：「订单接口是分页的吗？」
- 接口分页 → page/pageSize 传给接口，翻页重新请求。
- 列：订单号左对齐、金额右对齐、时间用项目格式化工具、状态列显示可读文案（不是 0/1）。
- 空数据 / 加载骨架 / 失败重试，三态齐全。
- 没做排序、没做筛选、没做导出——用户没要。

不该产出：一个把接口数组直接 map 成 `<tr>`、金额显示 `undefined`、翻页靠 slice 的表格。

## 最小路径（用户说「先随便展示一下」时）

- 可以砍：分页（仅数据少时）、长文本省略、时间格式化。砍掉分页 ≠ 用 slice 假装分页。
- 不许砍：空数据态、失败态、加载态。
- 仍禁止裸 happy path。
